Board 01 · /auth and first run

Two questions, then something useful.

Your current wizard asks across four steps before the app does anything. The benchmark says drop-off spikes after two. This board reshapes entry around a single idea: show a real calorie target before asking for anything optional.

What we take from whom

  • MyFitnessPalAsk goal, weight and activity, then compute a personalised target immediately. The payoff arrives before the user has done anything else. This is the one thing their onboarding does better than everyone.
  • MealimeLet people choose guidance over configuration. A "just pick sensible defaults for me" path that is not framed as skipping.
  • BenchmarksTwo questions maximum before value. Permissions asked at the moment of use, never up front.
  • MacroFactorIts steep learning curve is the warning, not the model. Depth is opt-in and lives behind the first success.

Concept A — the split screen, fixed

/auth Keep the layout, fix the form

Why keep it: the two-panel split already looks premium and the honest "Coming Soon" labels on Google and password reset are exactly right. The problems are all mechanical — the audit confirmed Enter does nothing and screen readers announce the password field as a row of bullets.

The five mechanical fixes

  • Wrap the fields in a real <form> so Enter submits.
  • Pair every <label for> with a matching id — the correct pattern already exists in your water-correction form.
  • Add autocomplete, switched between current-password and new-password by mode, so password managers behave.
  • Give the error box role="alert".
  • Disable both inputs while the request is in flight, not just the button.

Target: 3 actions to sign in — focus email, type, Enter.

The unit question, solved once

What is broken today

Metric is your default, but the calculator always converts from pounds, the weight box always prints lbs, height only accepts feet and inches, and the rate slider says lbs / week. A 75 kg user is costed as 34 kg and under-fed by roughly 635 kcal a day.

pattern The unit is part of the input, not a label beside it

Design answer: make the unit a segmented control welded to the field, not static text floating at the right edge. If the unit is tappable and visibly stateful, it cannot silently disagree with the value — and the ambiguity that hides the bug disappears.

178 field shape changes with the unit
  • Toggling the unit converts the number rather than reinterpreting it.
  • The height field changes shape — one box for cm, two for ft/in.
  • One helper, formatWeight(value, unit), owns every weight string in the app. Four files currently decide this on their own.

The escape hatch

The wizard is currently a full-screen overlay whose only exit is a successful save, and Skip Setup only appears on step 0. Its own error message says "please retry before leaving this screen" — but there is no way to leave. In the new shape:

  • Use sensible defaults is visible on every step, framed as a real choice rather than as skipping.
  • If a save fails, an inline banner offers Retry and Continue without saving.
  • The overlay is dismissible with Escape, and a persistent card on the Dashboard offers to finish setup later.
